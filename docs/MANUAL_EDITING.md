# Ручная правка установленного перевода

[← К оглавлению](../README.md) · [Редактируемые исходники](EDIT_TRANSLATION.md)

Правка непосредственно в сохранении удобна для проверки одной реплики. Для постоянной версии перенесите результат в исходники репозитория и соберите новый набор, иначе исправление не попадёт к другим игрокам.

Перед редактированием закройте игру/сервер и скопируйте изменяемый файл. Бинарные `.mca`, `.dat` и `.nbt` не редактируют обычным текстовым редактором.

## Диалоги, чат и меню датапака

Откройте `saves/<мир>/datapacks/hi_drehmal.zip`. Датапак должен сохранить структуру: `pack.mcmeta` и `data/` находятся в корне ZIP, без дополнительной папки-обёртки.

Основные места поиска:

```text
data/dialogue/functions/           диалоги основных персонажей
data/quests/functions/             побочные задания и реплики NPC
data/core/functions/               сюжет, база и системные события
data/players/functions/            настройки, сообщения игрока, AvPod
data/dlc/functions/modify/         станция и меню улучшения предметов DLC
data/terminus/functions/           сообщения и элементы Terminus
data/*/advancements/               названия/описания достижений в JSON
```

Не каждый путь присутствует в базовой редакции: папки DLC не добавляют в неё вручную.

Пример сообщения:

```mcfunction
tellraw @s [{"text":"Усилить предмет","color":"gold","clickEvent":{"action":"run_command","value":"/trigger example set 1"}},{"text":" — прибавка к броне","color":"gray"}]
```

Меняют только значения `text` и текстовые компоненты подсказок. В примере нельзя переводить `tellraw`, `@s`, `color`, `gold`, `clickEvent`, `action`, `run_command`, `value`, `trigger` или менять `example`/`1`: это структура, цвета и действие кнопки. Сам пример вымышленный и не предназначен для вставки в карту как новая команда.

В актуальном DLC команды кнопок могут содержать `/dlccall`. Сохраняйте команды именно вашей версии; не заменяйте их командами из старого английского или русского файла целиком.

Полезный поиск по распакованной копии:

```powershell
rg -n "искомая фраза|tellraw|hoverEvent" data
```

После правки пересоберите ZIP с прежним корнем и положите его обратно. Если есть одновременно ZIP и распакованная копия того же активного датапака, уберите дублирование из рабочего мира. Войдите в мир заново; команда `/reload` полезна при разработке функций, но не перечитывает все изменённые NBT-данные сохранения.

## Книга или предмет уже находится в мире

Его текст может быть сохранён в сундуке, инвентаре игрока, выброшенном предмете или жителе. Правка команды выдачи изменит будущую выдачу, но не обязательно уже существующую копию.

Для NBT используйте, например, [NBTExplorer от jaquadro](https://github.com/jaquadro/NBTExplorer), который поддерживает `.dat`, `.nbt` и Anvil `.mca` ([исходники и список форматов](https://github.com/jaquadro/NBTExplorer#supported-formats)). Открывайте только копию закрытого мира.

Типичные пути для Minecraft 1.20.1:

| Объект | Где искать текст |
|---|---|
| Книга-предмет | `tag/pages`, `tag/title`, при наличии `tag/filtered_title` |
| Имя предмета | `tag/display/Name` — JSON, записанный строкой |
| Описание предмета | `tag/display/Lore` — список JSON-строк |
| Предметы игрока | `playerdata/<UUID>.dat`, `Inventory`/другие инвентари |
| Сундук/бочка/кафедра | `region/*.mca`, блок-сущность в `block_entities` |
| Житель, рамка, стойка, выброшенный предмет | `entities/*.mca`, запись сущности |
| Командный блок | `region/*.mca`, `block_entities/.../Command` |
| Табличка 1.20.1 | `front_text/messages`, `back_text/messages` |
| Старые форматы табличек | `Text1` … `Text4` |
| Сохранённые шаблоны и переменные датапаков | `data/command_storage_*.dat` |

В некоторых данных игрока есть копии в `level.dat`; не считайте один найденный экземпляр единственным. В иных измерениях ищите такие же папки внутри `dimensions/...`, `DIM-1` или `DIM1`.

Обычную страницу `{"text":"Первая строка.\nВторая строка."}` можно изменить, сохранив JSON. `\n` внутри JSON означает перевод строки. Если JSON вложен в другую JSON- или SNBT-строку, появляется дополнительное экранирование. Не удаляйте обратные слеши «для красоты».

Для большого книжного текста лучше [править страницы в исходниках](EDIT_TRANSLATION.md): они представлены объектами JSON, а не цепочками экранированных строк.

## Подписи существ и технические поля

`CustomName` — отображаемое имя сущности, но иногда карта обращается к сущности через селектор `name=...`. Такие служебные имена сохраняют точно; список известных имён есть в `translation/protected.json`.

Поле `Name` само по себе **не означает видимый текст**. Например, `Objectives/.../Name` в scoreboard и `Attributes/.../Name` — технические имена, которые не переводятся. Имя предмета в `display/Name` и имя полосы босса — другой контекст. Не выполняйте глобальную замену одинаковых значений во всех полях `Name`.

Сохраняйте ID предметов/сущностей, `UUID`, `Tags`, координаты, счётчики, `CustomModelData`, значения атрибутов, селекторы, пути функций и командные аргументы.

## Русский ресурспак

Откройте `resourcepacks/Drehmal_RU.zip`, затем `assets/minecraft/lang/ru_ru.json`. Меняется правая сторона записи, например:

```json
"item.minecraft.emerald": "Чешуйка"
```

Это пример валюты карты, а не предложение заменить её на ванильное «изумруд». Учитывайте роль предмета в игре. Пакет должен сохранить `pack.mcmeta` в корне; не меняйте расширение на `.zip.zip`.

Перезагрузите ресурсы `F3+T` или перезапустите игру. Шрифты `ru_sign_*` нужны для табличек: перенос этого поля в имя моба уменьшит и его подпись.

## Проверка результата

Сравните с копией: в функциях должны отличаться текстовые значения, в NBT — нужные подписи/страницы. Для ZIP проверьте, что он открывается и содержит все прежние файлы. Затем проверьте в игре и текст, и связанную механику: действие кнопки, выдачу предмета, продолжение задания.

Не подменяйте целый `.mca` файлом из чужого NEW ради одной реплики: вместе с ним заменятся территория и состояние сущностей/сундуков этого региона. Используйте точечную правку NBT или установщик перевода.
