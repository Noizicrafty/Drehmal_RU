# Как дорабатывать перевод и собирать свои версии

[← К оглавлению](../README.md) · [Ручное изменение мира](MANUAL_EDITING.md)

## Что считать источником

`data/translation_payload.json.gz` — готовая проверенная база. `translation/` и `resourcepack/` — редактируемые исходники. Сборщик пишет результат в `dist/`, не изменяя готовую базу в `data/` и не открывая ваше сохранение.

Для собственной версии нужен Python 3.11+; внешние Python-библиотеки для сборщика и движка не требуются. Сам установщик сохранений рассчитан на Windows из-за блокировки мира через `msvcrt`.

## Самый простой способ: overrides

Откройте `translation/overrides.json` и добавьте точную исходную английскую фразу в `text`:

```json
{
  "text": {
    "Click to open the Primal Journey Completion Survey": "Нажмите, чтобы открыть опрос о прохождении Primal Journey"
  },
  "strings": {},
  "json_strings": {},
  "books": {}
}
```

Не ищите и не заменяйте эту фразу по всему бинарному миру. Сборщик сам переносит такое исправление в совпадающие точные компоненты и контекстные реплики, а старые снимки целых файлов отключает, чтобы они не вернули предыдущий текст.

Сохраняйте значимые пробелы, скобки и переводы строк. В игре предложение может быть собрано из нескольких разноцветных частей: прочитайте сообщение целиком, прежде чем редактировать один кусок.

## Общий словарь и контекстные замены

| Файл | Как редактировать |
|---|---|
| `text.json` | Слева точный оригинал, справа русский текст. Не меняйте левую сторону для уже существующей строки |
| `strings.json` | Точная NBT-строка → её замена. Внутри могут быть экранированные JSON-компоненты |
| `json_strings.json` | Канонически сериализованный исходный JSON → строка русского JSON |
| `chat.json` | Ключ описывает текстовую структуру сообщения. Строки значения: `[путь, оригинал, перевод]`; редактируется третье поле |
| `protected.json` | Служебные имена, которые используются для поиска сущностей; не переводятся |
| `member_templates.json.gz` | Готовые файлы датапаков, адресуемые SHA256 исходного содержимого; вручную их обычно не правят |

У движка несколько уровней: узнаваемый файл целиком, контекстное сообщение, точная строка/компонент, общий словарь. Поэтому изменение только последнего уровня без пересборки может не проявиться. `tools/build.py` сравнивает исходники с базой, синхронизирует изменённые словарные значения с более точными слоями и отключает снимки файлов для пользовательской сборки.

Пользовательские `strings` и `json_strings` из `overrides.json` имеют приоритет над соответствующими таблицами. Это инструменты точечной правки для опытного редактора: они не позволяют свободно менять команды, ID, селекторы или игровые данные.

Прямое изменение `chat.json` подходит для одного контекста, когда одинаковая английская фраза должна звучать по-разному у разных персонажей. Общий `text`-override, напротив, распространяется на все совпавшие фразы. Нельзя менять пути JSON-полей и исходную английскую колонку ради удобства: они нужны для сопоставления с картой.

## Книги

В `translation/books/` лежат отдельные JSON-файлы, названные по ID. Поиск по русскому тексту:

```powershell
rg -n "фрагмент предложения" translation/books
```

В каждом файле:

- `id` — стабильный ID записи;
- `title` — справочное название для редактора, а не команда изменения NBT-заголовка;
- `source_key` — нормализованный полный оригинал для распознавания книги; его не меняют;
- `pages` — список JSON-компонентов русских страниц, который попадает в сборку.

Редактируйте `text` внутри `pages`; сохраняйте цвет, курсив, жирность и интерактивные элементы. Для названия самого предмета-книги нужен отдельный перевод исходного `title` в словаре либо ручная правка тега `title` в NBT.

Можно заменить книгу целиком через `overrides.json`:

```json
{
  "text": {},
  "strings": {},
  "json_strings": {},
  "books": {
    "2a4bc982d7d3eef1": [
      {"text": "Полностью вычитанная первая страница."},
      {"text": "Продолжение с учётом контекста первой страницы."}
    ]
  }
}
```

Это пример структуры, не готовое исправление конкретной книги. Сборщик принимает 1–100 страниц. Ограничение NBT-строки в байтах не гарантирует, что текст поместится в окне книги: переносы и каждую страницу проверяют в игре. Не удаляйте `clickEvent` и `hoverEvent` из интерактивных книг.

Один проверенный текст на вымышленном языке (`Velmi artrid...`) оставлен в оригинале и не входит в 427 русских книжных шаблонов.

## Ресурспак

Правьте `resourcepack/assets/minecraft/lang/ru_ru.json`. Ключи вида `item.minecraft.emerald` являются идентификаторами; переводится только значение. Эта карта переиспользует обычные предметы Minecraft, поэтому перевод нужно сверять с их ролью в Drehmal, а не со стандартным названием в ванильной игре.

Файлы `assets/minecraft/font/ru_sign_2.json` … `ru_sign_7.json` используются для размера текста табличек. Не назначайте их именам мобов, предметам и чату. Движок отдельно ограничивает такие шрифты контекстом табличек.

## Сборка

Из корня репозитория:

```powershell
python tools/build.py
```

Получатся `dist/Drehmal_RU_Patch/` и `dist/Drehmal_RU_Patch.zip`, обновлённые SHA512 в двух манифестах и `dist/build_report.json`. При сборке без runtime батник использует установленный `python` из PATH.

Чтобы сделать переносимый набор для Windows x64, скачайте [официальный embeddable Python 3.13.1](https://www.python.org/ftp/python/3.13.1/python-3.13.1-embed-amd64.zip) и выполните:

```powershell
python tools/build.py --runtime-zip "C:\Downloads\python-3.13.1-embed-amd64.zip"
```

Выходную папку можно задать через `--output`. Для каждой итоговой сборки сохраняйте её собственные контрольные суммы. После правок `.gz` или ресурспака не копируйте старый `manifest.json`: установщик отвергнет несовпадение SHA512.

В репозитории также лежит `installer/install.py` — служебная основа больших офлайн-наборов. Обычная точка входа этого проекта — `Install_RU.bat` / `installer/existing.py`. Для новой игры используйте гайды установки оригиналов, а не запускайте служебный модуль без его полного набора файлов.

## Проверка перед публикацией

```powershell
python -m unittest discover -s tests -v
```

Затем примените сборку к **копии** нужной редакции мира. Проверьте весь разговор, соседние задания, предмет/книгу до и после получения, всплывающие подсказки и действие каждой изменённой кнопки. Отдельно проверьте повторное применение и восстановление резервной копии.

Для хорошего русского читайте всю книгу или цепочку диалогов: кто говорит, кому, о каком предмете, что уже произошло и что предстоит. Согласуйте падежи, род и время глаголов. Для латинского имени лучше естественная конструкция «письмо от Khive» или «в городе Firteid», чем изменение написания имени русским окончанием. Обычные английские слова переводятся по смыслу; вымышленные термины сохраняются.

Файл `build_report.json` сообщает, что включены пользовательские правки и отключены снимки файлов. Это не свидетельство прохождения игры: проверка текста и механики после редакторских изменений остаётся отдельным этапом.
